## 1. 프로젝트 개요

### 어떤 서비스인가

TALKI는 발표를 앞두고 막연한 불안을 느끼는 사람들을 위한 AI 발표 코칭 서비스입니다.

발표 연습을 할 때 가장 큰 어려움은 두 가지입니다. 첫째는 **혼자서 연습할 환경이 없다**는 것, 둘째는 **내가 잘하고 있는지 알 수 없다**는 것입니다. 거울 앞에서 혼자 연습하거나 영상을 찍어도, 어디가 어떻게 부족한지 구체적인 피드백을 얻기 어렵습니다.

TALKI는 이 두 가지 문제를 해결합니다. 화상 회의, 강당, 강의실 등 실제 발표 상황과 유사한 환경을 화면으로 재현하고, AI가 발표 내내 사용자의 시선·자세·발화를 분석하여 발표가 끝난 뒤 상세한 피드백 리포트를 제공합니다.

### 누구를 위한 서비스인가

- 면접이나 발표를 앞두고 실전 감각을 키우고 싶은 사람
- 발표 후 "어디가 문제였는지" 구체적으로 알고 싶은 사람
- 부담 없이 반복 연습하며 말하기 실력을 키우고 싶은 사람

### 나의 역할

| 담당 영역 | 주요 내용 |
|-----------|-----------|
| 메인 랜딩 페이지 | 서비스 소개 및 진입 UI 전체 구현 |
| 홈 대시보드 | 연습 이력, 스트릭, 최근 리포트 화면 구현 |
| 실시간 실전 페이지 | 발표 진행 및 실시간 분석 화면 구현 |
| 분석 결과 세부 페이지 | 5개 항목 결과 시각화 및 영상 리뷰 구현 |
| 연습 모드 3종 | 즉흥 말하기 · 키워드 구성 · 핵심 파악 구현 |

## 2. 주요 기능 상세

---

### 2.1 메인 랜딩 페이지

#### 왜 이 페이지가 중요한가

TALKI가 어떤 문제를 해결하는 서비스인지, 어떤 기능을 제공하는지를 처음 방문한 사용자에게 자연스럽게 전달해야 합니다. 한 페이지에서 너무 많은 정보를 한꺼번에 보여주면 오히려 이해가 어렵습니다.

#### 어떤 경험을 제공하는가

랜딩 페이지는 7개 섹션으로 구성되며, 스크롤을 내릴수록 서비스의 맥락이 쌓여가는 방식으로 설계했습니다.

- **Hero 섹션**: "발표가 두려운 당신을 위해"라는 공감 메시지와 함께 서비스 진입 버튼을 제공합니다.
- **고민 공감 섹션**: 사용자가 발표에서 흔히 겪는 어려움을 제시해, "이건 나 얘기다"라는 공감을 이끌어냅니다.
- **기능 소개 섹션**: 실전 모드와 연습 모드의 기능 카드들이 스크롤에 따라 하나씩 펼쳐집니다. 빠르게 스크롤하면 빠르게, 천천히 내리면 천천히 카드가 열리는 방식입니다.
- **요구사항 · FAQ · CTA**: 서비스 이용 환경과 자주 묻는 질문으로 진입 장벽을 낮춥니다.

#### 사용자 유입 흐름

```
첫 방문 → 공감 · 기대감 형성 → 기능 이해 → 회원가입 또는 로그인
```

스크롤만으로 서비스 전체를 이해하고 자연스럽게 가입까지 이어질 수 있도록 흐름을 설계했습니다.

### 2.2 메인 홈 대시보드

#### 왜 이 페이지가 중요한가

로그인한 사용자가 처음 마주하는 화면입니다. "오늘 어디서부터 시작할까?"를 바로 결정할 수 있어야 합니다. 그러기 위해서는 내 현재 상태와 다음 행동이 한눈에 보여야 합니다.

#### 어떤 경험을 제공하는가

홈 화면은 두 영역으로 나뉩니다.

**왼쪽 패널** — 나의 연습 현황
- 연속으로 몇 일째 연습했는지 스트릭과 이번 주 요일별 연습 여부를 한눈에 확인할 수 있습니다.
- 가장 최근에 기록한 마음가짐 메모가 표시되어, 연습을 시작하기 전 마음을 다잡을 수 있습니다.
- 가장 최근 발표 리포트의 총점과 주제가 간략하게 요약되어, 지난 연습의 결과를 바로 확인할 수 있습니다.

**오른쪽 패널** — 월별 캘린더 또는 성장 그래프
- 화살표 버튼으로 달력 보기와 그래프 보기를 전환할 수 있습니다.
- 달력에서는 어느 날 연습했는지, 그래프에서는 점수 변화 추이를 확인할 수 있습니다.

#### 주요 기능 탐색 구조

홈 화면은 현황 파악과 동시에 다음 행동으로 빠르게 이어지도록 설계했습니다. 실전과 연습 모두 홈에서 몇 번의 클릭으로 바로 시작할 수 있습니다.

---

### 2.3 실시간 실전 페이지

#### 왜 이 기능이 필요한가

단순히 카메라를 켜고 발표하는 것과, 실제 발표 환경과 유사한 화면을 보며 발표하는 것은 긴장감이 다릅니다. TALKI의 실전 모드는 사용자가 설정한 발표 유형에 맞는 배경 영상을 보여줌으로써 실제에 가까운 상황을 만들어냅니다.

#### 발표 진행 과정

발표 시작까지의 흐름은 다음과 같습니다.

```
5초 카운트다운 (자세 세팅)
        ↓
발표 시작 (영상 녹화 + 실시간 분석 동시 진행)
        ↓
실시간 피드백 메시지 수신 (토글 활성화 시)
        ↓
종료 버튼 클릭 → 영상 업로드 → 분석 결과 대기
```

카운트다운 5초는 단순한 연출이 아닙니다. 이 시간에 사용자가 카메라 앞에 제대로 자리를 잡고, 이후 녹화되는 영상에는 실제 발표 내용만 담기도록 하기 위함입니다.

#### 사용자가 설정할 수 있는 것

발표 전 카테고리 설정 화면에서 두 가지 옵션을 선택할 수 있습니다.

- **실시간 피드백**: 발표 중 말 속도나 자세에 문제가 생기면 화면 하단에 즉각적인 알림을 받습니다.
- **돌발 상황**: 예기치 않은 상황에 대응하는 훈련을 위해 돌발 질문이나 소음이 삽입됩니다.

두 기능은 토글로 언제든 켜고 끌 수 있어, 그날의 연습 목표에 맞게 조절할 수 있습니다.

#### 사용자 경험

발표 화면에서는 불필요한 요소를 최소화했습니다. 배경 영상과 음성 파형, 그리고 하단의 간단한 컨트롤만 보입니다. 발표에만 집중할 수 있는 환경을 만들기 위해서입니다.

### 2.4 실시간 분석 세부 결과 페이지

#### 왜 이 페이지가 중요한가

발표가 끝난 뒤 "잘한 것 같은데?"라는 막연한 느낌이 아니라, 어디가 좋았고 어디를 고쳐야 하는지 구체적으로 알아야 다음 발표가 달라집니다. 결과 페이지는 사용자가 자신의 발표를 객관적으로 돌아볼 수 있는 공간입니다.

#### 기본 분석 — 모든 사용자에게 제공

발표 종료 후 바로 확인할 수 있는 기본 결과입니다.

- **종합 점수**: 0~100점으로 이번 발표를 한 줄로 요약합니다.
- **4개 항목 점수**: 발화 속도, 시선 집중도, 주제 적절성, 제스처 안정성 각각의 점수가 원형 그래프로 표시됩니다. 점수에 따라 색이 달라져(빨강·주황·초록) 어느 항목이 취약한지 한눈에 파악할 수 있습니다.
- **추임새 점수**: "음", "어" 같은 추임새를 얼마나 사용했는지를 수치로 보여줍니다.
- **AI 피드백 텍스트**: 잘한 점, 개선할 점, 다음 연습 방향을 구체적인 문장으로 제시합니다.

#### 세부 분석 — 프리미엄 사용자에게 제공

페이지를 내리면 5개 항목의 세부 분석이 순서대로 나타납니다. 한꺼번에 보여주지 않고 스크롤에 따라 하나씩 등장하는 방식으로, 많은 정보를 자연스럽게 소화할 수 있도록 했습니다.

| 섹션 | 확인할 수 있는 것 |
|------|----------------|
| 음성 분석 | 분당 발화 속도(WPM)와 적정 범위 비교, 반복어 분석 |
| 시선 분석 | 카메라를 응시한 비율(%), 시선 처리 피드백 |
| 행동 분석 | 자세가 불안정했던 비율, 문제 구간 타임스탬프 |
| 발표 내용 분석 | 주제 적절성·시선 집중도·제스처 안정성 삼각형 레이더 차트 |
| 전체 분석 | AI가 종합적으로 평가한 발표 총평 |

#### 영상 타임스탬프 리뷰

행동 분석 섹션에서는 발표 영상을 직접 확인할 수 있습니다. 자세가 흔들린 구간, 말 속도가 급격히 변한 구간, 돌발 질문이 등장한 구간이 목록으로 정리되어 있으며, 항목을 클릭하면 영상이 해당 시점으로 바로 이동합니다. 1시간짜리 발표를 처음부터 끝까지 되돌려보지 않아도 핵심 구간만 빠르게 확인할 수 있습니다.

### 2.5 즉흥 말하기 연습

#### 왜 이 연습이 필요한가

실전 발표에서 가장 당황스러운 순간은 예상치 못한 질문을 받았을 때입니다. 즉흥 말하기 연습은 처음 보는 주제에 대해 빠르게 생각을 정리하고 말하는 능력을 키우는 훈련입니다.

#### 사용자가 어떻게 연습하는가

1. 화면에 랜덤으로 선택된 질문이 표시됩니다.
2. 마이크 버튼을 누르면 10초 준비 시간이 주어집니다. 어떻게 말할지 생각할 시간입니다.
3. 준비 시간이 끝나면 자동으로 30초 발표가 시작됩니다.
4. 발표가 끝나면 TALKI의 간단한 피드백이 나타납니다.

#### 어떤 도움을 받을 수 있는가

연습 중에는 화면 한쪽에 코칭 말풍선이 표시됩니다. "완벽한 답변보다는 끝까지 말하는 것에 집중하세요"처럼, 그 순간 사용자에게 필요한 한 마디를 전달합니다. 발표가 끝난 뒤에는 시간을 충분히 활용했는지, 추임새는 적절했는지 등을 간결하게 알려줍니다.

---

### 2.6 키워드 기반 구성 연습

#### 왜 이 연습이 필요한가

발표를 잘하려면 말하고 싶은 내용을 논리적으로 구성하는 능력이 필요합니다. 키워드 기반 구성 연습은 주어진 3개의 키워드를 자연스럽게 연결하며 발표를 완성하는 훈련으로, 생각을 구조화하는 연습을 돕습니다.

#### 발표 구조를 만드는 과정

화면에 3개의 키워드 카드(예: 협업, 문제해결, 성장)가 표시됩니다. 사용자는 이 키워드를 모두 포함하여 10초 준비, 30초 발표를 진행합니다.

발표가 끝나면 3개 중 몇 개의 키워드를 사용했는지, 키워드 간 연결이 자연스러웠는지를 분석해 보여줍니다. 사용한 키워드는 초록색으로 강조되어 시각적으로 확인할 수 있습니다.

#### 키워드 활용 방식

단순히 키워드를 나열하는 것이 아니라 논리적으로 엮는 것이 핵심입니다. "협업을 통해 문제해결 능력을 키웠고, 그 과정에서 성장을 경험했습니다"처럼 자연스러운 흐름을 만드는 것을 목표로 합니다. 코치 말풍선이 "키워드를 억지로 넣기보다는 자연스러운 흐름을 만들어보세요"라고 방향을 안내합니다.

---

### 2.7 핵심 파악 연습

#### 왜 이 연습이 필요한가

발표에서 중요한 것은 모든 내용을 말하는 것이 아니라, 핵심을 골라 간결하게 전달하는 것입니다. 핵심 파악 연습은 긴 텍스트에서 중요한 내용을 추려내고, 그것을 짧은 시간 안에 말로 표현하는 능력을 훈련합니다.

#### 핵심 내용을 분석하는 과정

긴 지문이 화면에 제공됩니다. 사용자는 지문을 읽으면서 10초 안에 무엇이 핵심인지 파악하고, 30초 동안 그 핵심을 자신의 말로 요약해서 발표합니다.

발표가 끝나면 지문에서 제시된 핵심 키워드를 얼마나 포함했는지 확인할 수 있습니다. "의사소통, 경청, 협업 중 2개를 활용했습니다"처럼 구체적인 결과를 보여줍니다.

#### 학습 효과

반복적으로 연습하면 텍스트를 빠르게 분석하는 능력이 생깁니다. 발표 준비 시간이 부족할 때 자료를 보고 핵심을 빠르게 파악해 발표하는 실전 상황과 동일한 구조입니다.

### 실전 발표 중 데이터 흐름

사용자가 발표하는 동안 세 가지 채널이 동시에 동작합니다.

```
사용자 발표 중
      │
      ├─── 카메라 ──▶ AI 분석 (시선·자세) ──▶ WebSocket ──▶ 실시간 피드백
      │
      ├─── 마이크 ──▶ 음성 처리 ──────────▶ WebSocket ──▶ 발화 분석
      │
      └─── 영상 녹화 ───────────────────────────────────▶ 종료 후 리포트
```

실시간 피드백은 발표 도중 즉각적으로 전달되고, 영상 녹화는 발표가 끝난 뒤 AI가 정밀 분석하는 데 사용됩니다.

### 연습 모드 공통 흐름

3가지 연습 모드는 동일한 4단계로 진행됩니다.

```
[ 대기 ]  ──▶  [ 준비 10초 ]  ──▶  [ 발표 30초 ]  ──▶  [ 피드백 확인 ]
  │                 │                    │                    │
마이크 버튼          카운트다운              녹음 진행            결과 표시
  클릭              (자동 전환)            (자동 종료)          다음 단계로
```

준비에서 발표로의 전환, 발표 종료는 모두 자동으로 이루어져 사용자가 시간을 따로 신경 쓰지 않아도 됩니다.

### 기술 스택

| 분류 | 기술 | 역할 |
|------|------|------|
| UI | React 19 + TypeScript | 화면 구성 및 상태 관리 |
| 빌드 | Vite | 개발 서버 및 프로덕션 빌드 |

| 컴퓨터 비전 | MediaPipe | 브라우저에서 직접 얼굴·자세 분석 |

## 5. 트러블슈팅 및 회고

### 문제 1 — 카운트다운 5초가 발표 분석에 포함되는 문제

발표 전 5초 카운트다운은 사용자가 자세를 잡는 시간입니다. 그런데 이 시간에도 카메라와 마이크가 분석 데이터를 수집하고 있어서, 사용자가 화면을 정리하거나 자세를 고치는 동작이 발표 데이터로 잡히는 문제가 있었습니다.

카운트다운 화면이 보이는 것과 실제 분석 녹화가 시작되는 시점을 분리하여 해결했습니다. 카메라는 카운트다운 중에 미리 준비를 완료하고, 카운트다운이 완전히 끝난 시점부터 녹화를 시작하도록 변경했습니다.

→ **발표 시작 이후의 데이터만 분석에 반영되어 결과 정확도 향상**

### 문제 2 — 홈 화면 닉네임 미표시

홈 화면에서 "OOO님, 반가워요!" 문구의 닉네임이 표시되지 않는 문제가 있었습니다. 네비게이션 바에서는 동일 계정의 닉네임이 정상 표시되고 있어서, 데이터 자체의 문제가 아니라는 것을 먼저 확인했습니다.

홈 화면이 데이터를 가져오는 API 엔드포인트가 오류를 반환했고, 닉네임과 연습 이력이 같은 요청 안에 묶여 있었기 때문에 둘 다 화면에 표시되지 않는 상황이었습니다.

닉네임 요청과 연습 이력 요청을 완전히 분리하고, 닉네임은 네비게이션 바와 동일한 방식으로 가져오도록 수정했습니다.

→ **어느 하나가 실패해도 다른 정보는 정상 표시되는 구조로 개선**

### 회고

이 프로젝트를 통해 가장 크게 달라진 시각은 **"기능이 동작한다"와 "사용자에게 제대로 동작한다"의 차이**를 인식하게 된 것입니다.

카운트다운 문제는 코드만 보면 아무 이상이 없습니다. 녹화가 시작되고, 데이터도 쌓이고, 영상도 업로드됩니다. 그러나 사용자 입장에서는 발표를 시작하기도 전의 데이터가 결과에 영향을 미치고 있었습니다. 직접 사용해보고, 사용자의 시선으로 화면을 바라보는 것이 얼마나 중요한지 배웠습니다.

또한 5개 페이지 이상을 담당하면서 공통으로 사용되는 UI 요소들을 하나의 컴포넌트로 정리하는 작업을 자연스럽게 하게 되었습니다. 처음에는 각 페이지에서 비슷한 코드가 반복되는 것을 당연하게 여겼지만, 한 곳을 수정하면 다른 곳도 함께 바뀌는 구조를 만들고 나서 유지보수가 얼마나 편해지는지 직접 체감했습니다.
